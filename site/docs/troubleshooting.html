Troubleshooting

Slate is an early preview, so now and then something may not look or behave as it should. Most things are put right by a restart, and your apps and windows stay open through it. This page has that, and what to try when it isn't enough.

Restarting Slate

If the bar, dock or a panel looks stuck or out of date, restart Slate. The screen fades to "Reloading Slate" and back, and everything you had open stays open.

  • In a terminal: slate restart (or slate restart --full to stop it completely and start it again).
  •  Settings → About → Restart the shell.
  • Right-click the control centre's mark on the menu bar and choose to restart Slate.

If Slate isn't running at all, slate on its own starts it. Open a terminal with Super + Return.

The Debug page

 Settings → Debug (a tile on All Settings) has fixes for when something hasn't caught up. Slate normally does all of this by itself, so you shouldn't often need it.

Reload everything

Reload reloads Hyprland's config and restarts Slate from scratch (the bar, dock, panels and Settings), then comes back to the Debug page. Your apps and windows stay open.

Resync the login screen

Slate's own login screen, if you've installed it, copies your wallpaper, settings, picture and font whenever you change them in Slate. If you changed one outside Slate (replaced the wallpaper file, or changed your picture, name or keyboard layout elsewhere), Resync brings it up to date.

Log detail

How much Slate writes to its log: Normal, Detailed or Everything. Turn it up while tracking down a problem, then back down. Changing it restarts Slate, so it asks first.

Export recent logs

Export saves Slate's recent log and details about your system to a text file in Downloads, to attach to a bug report. Your location is left out. The log can still name apps, windows and file paths, so look the file over before you share it.

Reading the log

Slate's log is ~/.cache/slate.log. To watch it as things happen, run slate log; slate logs does the same as Export above.

Common problems

Slate isn't on the login screen

Run sudo ~/.config/slate/bin/slate-session-install. Some login screens only look for new sessions after a restart.

The session starts and ends straight away

Usually Hyprland is too old, or start-hyprland is missing. Check Hyprland --version: Slate needs 0.57 or newer. If your session uses uwsm, journalctl --user -b -u 'wayland-wm@*' shows what went wrong. You can always pick your other desktop at the login screen in the meantime.

A black screen with a pointer, but no bar

Quickshell couldn't load Slate. Open a terminal with Super + Return and run slate to see the message, or look in ~/.cache/slate.log. If you've installed Quickshell from source (Ubuntu, Debian, openSUSE), a Qt update may mean it needs building again: packaging/build-quickshell.sh.

Icons show as boxes

Slate's icon font didn't load. Reinstalling Slate puts it back: ./install.sh --no-deps from the Slate folder.

A change to one of your own files didn't work

Slate shows a notification saying what's wrong and where. The rest of your config still loads, so fix it and save again. See Your own config.

An app didn't change colour

GNOME apps (Files, Text Editor and the like) read Slate's colours only when they start, so close and reopen them. Apps built with GTK 3 and Qt change straight away. See App theming.

A new pointer or setting hasn't reached everything

The pointer theme and other environment settings reach apps when they start. Apps already open keep the old ones, and Slate itself picks them up after you log out and in again.

Suspend, Restart or Shut down are missing

Or settings are greyed out with "This needs systemd or elogind". Your computer has no login service running. Run ~/.config/slate/bin/slate-init info: logind=none means elogind isn't installed or isn't started.

No sound, on a system without systemd

Check PipeWire is installed; Slate's session starts it. pgrep -a pipewire should show pipewire, wireplumber and pipewire-pulse.

Hyprbars stopped after a Hyprland update

Hyprbars, the optional title-bar plugin, needs rebuilding for each new Hyprland. Slate switches to its own title bars in the meantime and asks whether to rebuild. Rebuild, Retry and Remove are in  Settings → Windows.

Slate's login screen won't let you in

Slate's login screen falls back by itself to the last version that worked, then to a basic emergency login. If even that fails, switch to a text console with Ctrl + Alt + F3, log in, and run:

sudo ~/.config/slate/bin/slate-greeter-install --revert

then restart. That puts your previous login screen back.

Starting over

 Settings → Debug → Factory reset puts Slate back as it was when first installed: every setting to its default, and your dock pins, saved Spaces, launcher history, notifications, clipboard history, display layout and app theming forgotten. Your apps and windows stay open, and Slate restarts with the Welcome window.

  • It asks twice before anything changes.
  • Your own files are kept (hypr/ and user/), unless you switch on Also clear my own files, which swaps them for the blank ones Slate starts with.
  • Nothing is deleted. Everything is moved to ~/.local/share/slate/backups/factory-reset-<date>, so you can copy it back by hand.


There's no undo in Settings: putting things back from the backup folder is done by hand. If only one page needs resetting, Restore defaults on that page is gentler.

From a terminal, the same reset is ~/.config/slate/bin/slate-factory-reset, with --user-files to clear your own files too.

Reporting a problem

We'd be grateful to hear about anything that goes wrong, in a GitHub issue. To help us find it:

  1. If you can, turn Log detail up in Settings → Debug and make the problem happen again.
  2. Choose Export recent logs (or run slate logs), and look the file over.
  3. Say what you did, what you expected and what happened instead, and attach the file.

Then turn Log detail back to Normal. Thank you: every report helps.
