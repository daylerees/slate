Reference

Your own config

Settings covers almost everything, but if you like to keep your own config, you can. Your own Hyprland tweaks and QML live in files of your own, which Slate loads on top of its config and never overwrites.

Your files

Slate makes these for you the first time it starts, each with instructions and examples inside. They're empty of settings until you add some, so they change nothing to start with.

File, in ~/.config/slate/What it's for
hypr/env.luaEnvironment variables for your apps. Loaded first
hypr/variables.luaYour terminal, file manager, browser, editor and calculator; which screen is which; how many workspaces get number keys; the pointer theme and size
hypr/monitors.luaMonitor rules, and which workspaces go on which screen
hypr/binds.luaYour own keyboard shortcuts, or replacements for Slate's
hypr/rules.luaWindow and workspace rules
hypr/autostart.luaCommands to run when you log in
hypr/hyprland.luaAnything else for Hyprland. Loaded last, so it wins over everything
user/shell.qmlQML loaded into Slate itself: extra widgets, timers, commands of your own

They're written in Hyprland's Lua config. Its wiki, wiki.hypr.land, has everything you can put in them.

How they're loaded

The Slate session runs Hyprland with Slate's own config, and your files around it:

  1. env.lua and variables.lua, first, so Slate's config uses your choices.
  2. Slate's own config: colours, animations, inputs, shortcuts, window rules and so on.
  3. monitors.lua, binds.lua, rules.lua, autostart.lua and last hyprland.lua, so yours win wherever they overlap.

Your usual ~/.config/hypr belongs to your other Hyprland session and isn't read, so the two never get in each other's way.

With Settings

For Hyprland's side of things (keyboard, mouse, touchpad, focus, animations, default apps, the lid and the power button), Settings only sends what you change there. Anything you haven't changed keeps what your own files say. Where both set the same thing, your hyprland.lua wins, since it's loaded last.

Saving and mistakes

Saving one of your files applies it straight away: Hyprland's config reloads for the .lua files, and Slate reloads for shell.qml. Your apps and windows stay open.

If something in a file is wrong, Slate tells you in a notification, with what and where. A .lua file with a mistake is skipped while the rest still loads; a shell.qml with one leaves Slate running without it. Fix it and save again, and it's picked up.

Commands in autostart.lua run once when you log in, not every time the config reloads, so changes there apply from your next login.

Examples

Hyprland

-- hypr/variables.lua
TERMINAL = "foot"
BROWSER  = "chromium"

-- hypr/binds.lua
hl.bind("SUPER + B", hl.dsp.exec_cmd("firefox"), { description = "Apps: Firefox" })
hl.bind("SUPER + G", hl.dsp.exec_cmd(SLATE .. " ipc call spaces restore Coding"))

-- hypr/rules.lua
hl.window_rule({ match = { class = "^(Spotify)$" }, workspace = "5 silent" })

-- hypr/hyprland.lua
hl.config({ input = { kb_layout = "gb", kb_options = "caps:escape" } })
hl.config({ general = { gaps_in = 4, gaps_out = 8 } })

A shortcut with a description of "Group: what it does" shows in Settings → Shortcuts. SLATE is the slate command, so any of its actions can go on a key.

QML

user/shell.qml is loaded into Slate, so anything Quickshell can do works there, and Slate's own pieces too, such as Config.s for settings and Config.accent for the accent colour. The file has a small clock widget to try, and this, which adds a command of your own:

IpcHandler {
    target: "mine"
    function hello(): void { Quickshell.execDetached(["notify-send", "Hello from your shell.qml"]); }
}

Then slate ipc call mine hello runs it. Quickshell's docs have the rest.

Kept safe

  • Updates never touch them. settings.json, hypr/ and user/ are carried across to every new version, and going back to an earlier one keeps them too (Updates).
  • A factory reset leaves them alone unless you choose Also clear my own files, and even then they're moved to a backup folder rather than deleted (Starting over).
  • Slate's own files are replaced by updates. If you've edited one, Settings → Updates lists it before updating, and your copy stays in ~/.config/slate.previous. Your own files are the place for changes that last.

Settings → About

 Settings → About says what Slate is and its licence, how much memory and processor Slate itself is using right now, and a few tools:

  • Welcome: Show the welcome opens the Welcome window again.
  • Settings file: Open file opens settings.json, where every setting is kept.
  • Restart the shell: reloads the bar, dock, launcher, switchers and notifications. Your apps and windows stay open.
