Getting started

Updates

Slate looks for a new version once a day and lets you know with a notification. Updating takes one click, keeps your settings and your own tweaks, and keeps the version you had so you can go back.

Knowing there's a new version

When a new release is out, a notification tells you. You'll find everything about it in  Settings → Updates, which you can also reach from the control center's right-click menu.

The Version section shows the version you have, the latest one, and when Slate last checked. Check now looks straight away. If you'd rather Slate didn't look by itself, switch off Check for updates.

Your apps and the system

Updates for your apps and your computer's own system are in Software. Once a day Slate looks for them, and if any are waiting you get one calm notification, "Updates are waiting"; click it to open Software's Updates. It never looks in game mode or on a metered connection (a phone's hotspot, say).  Settings → Updates shows how many are waiting, with Open Software, and Tell me about app and system updates switches the notification off.

Updating

When there's a new version, Settings → Updates says so at the top, with Update now beside it and What's new in it right underneath, with a link to its release page. Choose Update now: Slate downloads it, puts it in place and restarts on the new version. While it does, the same row shows the step it's on, with a bar and how much has downloaded. Your apps and windows stay open.

Slate is installed once for everyone on the computer, so updating asks for an administrator's password. If you're not an administrator, someone who is can type theirs.

If Slate came with your system's packages (from your distro rather than its installer), it updates with the rest of your system instead, and Settings → Updates says so.

Before anything is unpacked or run, Slate checks the download against the checksum (a SHA-256) published with the release on GitHub, and checks it's signed with Slate's own key, so you know it was made by us and not just anyone who could publish on GitHub. If either doesn't match, or the release has no checksum or signature, Slate doesn't install it and says so; your Slate stays just as it was. It only ever downloads from Slate's own releases on GitHub, and only a version newer than the one you have.

Your settings and your own tweaks always come along: settings.json, hypr/ and user/ in ~/.config/slate.

  • If you've changed Slate's own files by hand (anything outside those three), Settings lists them before updating, since the update replaces them. Your versions stay in the copy kept below, and you'll be asked to confirm in Slate's confirmation window first.
  • If the new version needs new packages, or changes the login session, it asks for your password and installs them as it updates. If you cancel, or it needs a newer Hyprland or Quickshell than your distro has, it stops before changing anything and tells you what to do.
  • If an update doesn't finish, Settings says so, with Show log and Try again. Nothing is lost.

Each release's notes are also in the changelog.

Going back

Slate keeps the version you had before, in /usr/local/share/slate.previous. Under Previous version in Settings → Updates, Go back (and a confirmation in Slate's confirmation window) switches to it. Like updating, it asks for an administrator's password.

Your settings and tweaks stay just as they are now, and the version you leave is kept in its place, so you can switch back again the same way.

Missing packages

About half a minute after it starts, Slate checks that everything it needs is installed. If something's missing (a package removed since, say), a notification offers to install it, with your password. It asks once for each set of changes, and Later waits a week. To see what it would do, run /usr/local/share/slate/bin/slate-system --check.

Slate's helpers

When Slate asks for your password (to install a package, update the login session or login screen, or switch the camera for Private Mode), what it runs is a small helper kept in /usr/local/libexec/slate, where only root can change it, never a script in your home folder. Now and then an update changes those helpers, and updates from Settings can't reach that folder by themselves. So the same notification offers to copy the new ones over, with your password: Slate's helpers need updating. Until you say yes, the ones you have carry on working, and Later waits a week.

The login screen

If you've installed Slate's own login screen, it's updated separately, because it runs from a system folder before you log in. When its design changes, Slate asks with a Login screen out of date notification; Update asks for your password. Until then you'll see the previous version at login, which is quite safe. More in Locking and login.

From a copy of the code

If you installed from a clone of the repository and would rather update that way:

cd slate && git pull
./install.sh --no-deps

Your settings are kept, just as with an update from Settings.
